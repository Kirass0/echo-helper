# Map: Echo Helper web rewrite

Label: wayfinder:map

## Destination

A complete spec at `.scratch/web-rewrite/spec.md` for rewriting Echo Helper (the WPF app in `..\EchoHelperClaude`) as a static web app hosted on github.io, with nothing left to decide before it is sliced into implementation tickets. Building the app is a separate effort after this map.

## Notes

- **Source project is read-only.** Read `..\EchoHelperClaude` freely (Core, WPF views, `GLOSSARY.md`, `docs/adr/`), never edit it.
- **Plan, don't build.** Tickets produce decisions. Code written here is throwaway prototype only.
- **Fixed by the destination** (settled while charting, not open for re-decision):
  - Audience: a Wuthering Waves player who knows the game (Echoes, Substats, tuning) but has never seen this tool or its vocabulary. The app must work on first open with no setup or file editing, and explain its own concepts.
  - Scope: both existing tabs, Echo Evaluation (multi Value Table comparison, distribution chart) and Upgrade Strategy (Rule Groups, Discard Rates, Tuning Cost). The rewrite need not be 1:1.
  - Purely static: no backend, no accounts, all calculation in the browser.
  - Desktop-first, responsive, must not break on a phone. English only.
  - Value Tables ship built in, maintained by the repo owner; their weights come from several theorycrafters who must be credited in the app. Users can also add and edit Value Tables for their own use. This reverses the source project's ADR 0002.
  - Game data (Substat value sets, tier weights, Tuning Costs) in the old Core is trusted as current and ported as it stands in the source project from commit `53ce242`, which holds the Reference Roll patch (see [Which roll value each Substat type is normalised by](issues/15-reference-roll-values.md)).
  - No stack constraint: Blazor WebAssembly reuse versus a TypeScript port is decided on merits.
- **Vocabulary**: `GLOSSARY.md` at the repo root was carried over from the source project. Use its terms in every ticket and answer. Text written before [Which words the app shows a new player](issues/06-user-facing-vocabulary.md) uses the old names: Value Table is now Substat Weight Table, Echo Value is Echo Score, Target Value is Target Score, Median Roll is Reference Roll.
- **Skills**: grilling tickets use `grilling` and `domain-modeling`; prototype tickets use `prototype` (and `frontend-design:frontend-design` for anything visual); research tickets use `research`.
- **Subagents use the Opus model** (repo `CLAUDE.md`).
- **Research findings** go in `.scratch/web-rewrite/research/<NN>-<slug>.md`, linked from the ticket. This repo is not a git repository yet, so there is no `research/<name>` branch.

## Decisions so far

<!-- the index: one line per closed ticket, enough to judge relevance, then zoom the link for the detail the ticket holds -->
- [Blazor WebAssembly versus TypeScript: the facts](issues/01-blazor-wasm-vs-typescript-facts.md): Blazor reuses Core and its tests (~2,480 lines) untouched but costs ~3.3 MB gzip on Pages (gzip only, no Brotli without a JS decoder) and needs a Web Worker for off-thread work; TS rewrites Core but ships far less; ~5,970 WPF lines are rewritten either way; all WASM/JS speed figures are unmeasured estimates.
- [Which stack the web app is built on](issues/02-stack.md): a TypeScript port (strict), React with built-in state, Vite and npm, plain CSS Modules, Core as a plain module with no React or DOM imports, Vitest plus a few Playwright smoke tests, own SVG charts on `d3-scale`/`d3-shape`, tab in the URL hash with no router; the port-over-Blazor choice is ADR 0001.
- [How the new calculation is proven equal to the old one](issues/03-core-parity.md): equal means within `1e-9`; a structural port of Core proven by 70 ported tests, both sampling oracles and golden fixtures exported once from the C# Core (committed exporter in `tools/golden-export/`, 28 source Value Tables); afterwards the projects are independent and fixtures are regenerated from TypeScript when game data changes; the calculation method is ADR 0002; later comments add that the fixtures must cover Flat DEF through "Mornye" and that the source's summation order is kept.
- [The built-in Value Table catalogue and its credits](issues/04-value-table-catalogue-and-credits.md): Built-in Value Tables are baselines, not correct answers; one JSON file of `name` and `weights` only (no id, source, note or suggested Targets), the name is the identity, several tables per Resonator allowed; a general "thanks to..." mention of ChemX32, Maygi and riley, shown with the app's explanatory text; the owner edits the file and pushes; starts as the owner's 61 tables (most calculated with docs/substat-weights.md).
- [How users add and edit their own Value Tables](issues/05-custom-value-tables.md): Built-in Value Tables are read-only; a Custom Value Table is an independent copy or a blank table with its own unique name and no tie to its original; weights are finite and 0 or more, names at most 40 characters and unique ignoring case; edits are drafts with Save and Cancel; a custom rename carries remembered state along, a name taken by a new built-in renames the custom table to "(custom)"; one editor and one two-group picker list, look left to the UX prototypes.
- [Which words the app shows a new player](issues/06-user-facing-vocabulary.md): the on-screen label is always the glossary term, in code too; Value Table becomes Substat Weight Table, Echo Value becomes Echo Score, Target Value becomes Target Score, Median Roll becomes Reference Roll; the four rule kinds get plain names (Substat Count, Substat Roll, Echo Score, Target Chance); Success Rate and Successful Echo are new terms; a Tune Stage reads "Tune Stage 2/5 (+10)"; Rule Group stays a term but the design should not need to show it.
- [Which roll value each Substat type is normalised by](issues/15-reference-roll-values.md): a Reference Roll is the type's chance-weighted median roll, which changes Crit Rate to 7.5, Crit Damage to 15 and Flat DEF to 50 and leaves the other ten; the three values are already patched into the WPF project, so the golden fixtures can be exported; the web Core computes Reference Rolls from the possible values and tier weights and keeps no table, with a test pinning the 13 values; the weights copied from Maygi's sheet (crit, Flat DEF) and ChemX32's (DEF%) are rescaled by fixed ratios during the owner's catalogue recheck; Reference Rolls are explained in the help text only.
- [How Echo Evaluation looks and behaves](issues/07-echo-evaluation-ux.md): one Substat Weight Table in focus, the Echo as five tune slots filled by type grid then value buttons (cog to correct one), results as three rows of boxes (Target/ER Target Chance; Echo Score, Top/ER Top Percent; Median, Average, Best; Worst dropped), a 60-band distribution chart with other tables in grey, and below an aligned list of tables that is the only picker, holds each table's targets and opens a weights dialog by cog; no table limit, live results, first open is a prompt pointing at the real picker.
- [How Upgrade Strategy looks and behaves](issues/08-upgrade-strategy-ux.md): all five Tune Stages in one column with each stage's Discard Rate beside it and a results panel; rules joined by "and", alternatives by "or", no "Keep tuning if" and no Rule Group on screen; "Compare with another strategy" puts the strategy beside a blank second one (at most two, one shared Weight Table) with a difference table below, and "Stop comparing" discards the second; example strategies set Echo Scores as a Top x% of the selected table, worked out once on load; unfinished rules are highlighted and old results stay faded.
- [How a new player learns the app](issues/09-first-run-and-explanations.md): opens on Echo Evaluation (empty); Upgrade Strategy starts with "Crit first" and no Weight Table (behaviour without a table later changed by ticket 17); Target Score starts empty; no tour or welcome popup; a permanent purpose line per tab linking to About; short plain-text tooltips on a listed set of less-clear terms, marked by a dotted underline, hover or tap; a third tab, About, with seven anchored sections (incl. Reference Rolls, Crit Rate cap, per-table notes, credits, disclaimer); the spec fixes the exact short texts, About only as an outline.
- [What the browser remembers](issues/10-persistence.md): both tabs come back exactly as left (the Echo, listed tables, focus, targets per table name, the strategy with every rule kind's fields, Strategy B while comparing) plus Custom tables; not the tab (the hash keeps it) or Edit/Done mode; three versioned `localStorage` entries saved on every change and synced across open tabs; no named strategies, no backup file, no reset action; unavailable storage fails silently; deleting a Custom table forgets its targets.
- [How fast the ported calculation runs in a browser](issues/13-calculation-speed-in-the-browser.md): cost tracks a table's distinct Echo Scores (28k to 3.8M in the new catalogue); a straight TS port is 5–7× slower than C#, so a fresh Echo, the whole-table distribution and strategies with Echo Score, Substat Roll or Target Chance rules take hundreds of ms to ~10 s per table in Chrome/Edge, while 2/5+ Echoes and Substat Count strategies stay ≤ 32 ms; sorted arrays instead of `Map`s made the distribution 10–17× faster (beating C#) but change summation order.
- [Whether the TypeScript Core may use faster data structures than the C# one](issues/19-faster-core-data-structures.md): yes, anywhere in Core; results are judged within `1e-9`, not structure, but Echo Scores stay bit-exact with the source; the distribution and finishing tables use sorted typed arrays, the pass drops its string key; finishing tables are cached in memory per Weight Table and type set; the plain `Map` port is written first and kept in the tests as an exact reference; ADR 0002 amended, fixtures unchanged; expected ~50 ms median / under ~1 s worst on a desktop.
- [The visual direction](issues/11-visual-direction.md): direction A (calm, bordered panels, one indigo accent, filled-area distribution chart without target labels) in Onest; both themes, dark by default; one colour per Tune Stage and gold for Successful; pencil, sliders and × icon buttons instead of the cog; green/red pills in the strategy comparison; About gets a sticky side panel of its sections; switching tables or states never moves the layout.
- [Hosting and delivery on GitHub Pages](issues/12-hosting-and-delivery.md): public repo `Kirass/echo-helper` at `kirass.github.io/echo-helper/`, name kept after a collision check; one Actions workflow deploys on push to `main` only if type check, lint, Prettier, Vitest (incl. golden fixtures and a catalogue validity test), build and Chromium Playwright smoke tests pass; updates reach players by plain redeploy (data bundled, no service worker or notice); header shows "Updated 20 Nov 2026" on the right; disclaimer only in About, wording fixed; MIT, repo Issues for feedback; no analytics, cookies or third-party requests.
- [Whether calculations need a worker, progress and stale-result handling](issues/14-calculation-responsiveness.md): one Web Worker runs all Core work; newest input wins with per-table jobs (focused table, then list order; visible tab first), no Cancel, no Calculate button, no debounce; pending results fade with "Calculating…" after ~300 ms, no progress bar or extra stale warning; caches capped LRU (~10M entries), worker restarted once on failure then a reload message; speeds are guidance, no CI perf test; no ADR.
- [How the player switches between dark and light](issues/21-theme-switch.md): Dark and Light only, first open always dark (system setting ignored); a sun/moon icon button at the header's far right; remembered as a fourth versioned `localStorage` entry synced across tabs, applied before first paint by a tiny inline script; instant switch, CSS `color-scheme`, unreadable entry means dark.
- [What happens to stored data that no longer fits](issues/18-outdated-stored-data.md): each of the four entries is handled alone; older versions migrate forward by chained steps (an unmigratable entry resets only itself); unreadable values are salvaged at the smallest unit, silently except a one-time notice when Custom tables are lost; a vanished table drops its row (focus moves on) or empties the strategy's picker (the deploy notice was later dropped by ticket 17); an entry from a newer version is ignored silently and never overwritten.
- [The exact wording of the app's short texts](issues/17-short-text-wording.md): the final text of every tooltip (11; Median, chance per band, the Target Chance rule kind and "Where Echoes end" dropped), purpose line, prompt, notice, editor message, icon label and the page title; the chart is "Echo distribution" with axes "Final Echo Score" and "Chance" and stays at 5/5; Upgrade Strategy without a table shows only "Pick a Substat Weight Table above…" (examples and Compare disabled), takes the first table added on Echo Evaluation, and can't return to none; a built-in removed by a deploy disappears silently.
- [How both tabs work on a phone](issues/16-phone-layout.md): phone layout at 600px and below; B (Cards) everywhere: three-across result boxes with full terms, one card per Weight Table (no sideways scroll), rule rows with kind and × on line 1, popups as bottom sheets, comparing offered via an A | B switch with stacked difference rows; strategy results and About follow C: results below the stages with a sticky Success Rate bar at the bottom, About as an accordion.
- [How far accessibility and keyboard use go](issues/20-accessibility-and-keyboard.md): no WCAG target, audit or CI check, only small changes; native controls and a Tab/Enter/Space/Escape model with set focus moves; each Weight Table row is its own tab stop (Enter puts it in focus, so its controls never move the focus); the distribution chart gets a generated label and the other charts are hidden from screen readers; stage colours stay, but colour is never the only carrier; ▲/▼ for better and worse before each comparison pill; a 3:1 field border; one polite live line once results settle; reduced motion turns off all motion; 24px hit areas, nothing breaks at 320px.
- [Assemble the spec](issues/22-assemble-the-spec.md): [spec.md](spec.md) written with final behaviour only; assembling settled full "Top Percent" labels, relative comparison pills without a Success Rate row (rates shown in each compare summary), the full table picker on Upgrade Strategy, a confirmation before an example replaces rules, fixed number formats and field errors for invalid numbers.

## Out of scope

- **Building the app.** This map ends at the spec.
- **Owned-Echo inventory** (the never-built "Echo inspection" idea in the source project's `.scratch`). Not part of either existing tab.
- **Sharing links** for an Upgrade Strategy or an Echo Evaluation. Ruled out for now by the owner.
- **Import and export of Custom Value Tables**, or of the whole stored state as a backup file. Left out of the first version: sharing is already out, and a table is 13 numbers to retype ([What the browser remembers](issues/10-persistence.md)).
- **A library of saved, named Upgrade Strategies.** There is one working strategy, plus a second while comparing, and the examples; the source never had a library ([What the browser remembers](issues/10-persistence.md)).
- **Strategy Code and Copy Results.** A spreadsheet workflow specific to the original author; not shipped publicly.
- **Game imagery** (Resonator portraits, Substat icons). The UI is text only.
- **Localisation.** English only.
- **Backend, accounts, sync across devices.** Ruled out by static hosting.
- **Re-verifying game data** against the live game. Trusted as current.
